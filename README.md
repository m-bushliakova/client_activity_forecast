# client_activity_forecast

Прогнозирование общей суммы транзакций клиента в следующем месяце для планирования маркетинговых активностей.

## Цель проекта

Прогнозировать общую сумму транзакций клиента банка в следующем месяце и использовать этот прогноз для сегментации клиентов по ожидаемой активности, планирования и оптимизации маркетинговых активностей банка.

## Бизнес-задача

Заранее понимать, какую транзакционную активность проявит клиент в следующем месяце, чтобы:

* не тратить маркетинговый бюджет на неактивных клиентов,
* своевременно удерживать ценных клиентов,
* выявлять перспективных клиентов с растущей активностью.

## Общая логика решения

1. Предварительно сегментировать клиентов по масштабу исторической активности
2. Для массового сегмента построить ML-модель прогноза суммы транзакций
3. На основе прогноза выполнить бизнес-сегментацию клиентов
4. Использовать сегменты для принятия маркетинговых решений

## Эволюция проекта

### Фаза 1. Анализ исходного датасета

Изначально планировалось использовать датасет
[Bank Customer Segmentation (Kaggle)](https://www.kaggle.com/datasets/shivamb/bank-customer-segmentation).

В ходе детального EDA были выявлены критические ограничения:

* всего ~2.5 месяца транзакционных данных
* около 75% клиентов совершили только одну транзакцию
* невозможно построить временные признаки и лаги
* данные непригодны для задачи прогнозирования

Результаты анализа и принятое решение:

* `notebooks/02_eda_initial.ipynb`
* `notebooks/03_decision_document.ipynb`

### Фаза 2. Выбор нового датасета

После анализа нескольких альтернатив был выбран новый транзакционный датасет, который:

* содержит длительную историю транзакций (более 6 месяцев)
* включает миллионы транзакций и устойчивые клиентские паттерны
* позволяет строить временные ряды и лаговые признаки
* подходит для end-to-end ML-задачи прогнозирования

Обоснование выбора:

* `notebooks/03_decision_document.md`
* `notebooks/04_check_mbd_dataset.ipynb`

### Фаза 3-4. Анализ, Feature Engineering и подготовка финального датасета

На этом этапе выполнено:

* очистка данных
* анализ распределений сумм транзакций
* выбор основной валюты (currency = 11)
* выявление сильной асимметрии и длинного хвоста распределения

Предварительная сегментация клиентов по масштабу активности:

* массовые клиенты
* экстремально крупные клиенты (top 1%), для которых требуется отдельный аналитический подход

Создаются признаки на основе истории транзакций клиента:

* агрегаты по сумме и количеству транзакций
* лаговые признаки
* скользящие статистики
* признаки стабильности и тренда

Блокноты:
* `notebooks/05_full_eda.ipynb`
* `notebooks/06_preprocess_and_feature_eng.ipynb`


### Фаза 5. Моделирование

Для массового сегмента клиентов строится модель:

* вход: признаки по истории клиента
* выход: прогноз суммы транзакций в следующем месяце

На основе прогноза выполняется бизнес-сегментация клиентов:

* low activity
* at risk
* growth
* high value
